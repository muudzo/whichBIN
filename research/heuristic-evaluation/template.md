# Heuristic evaluation: template

A method from the *Evaluate* part of the Sprint 3 toolbox: check every screen against Nielsen's 10 usability heuristics and rate each problem. It finds problems without users, so test rounds can spend their time on what only users can show.

## How to run it

1. **Work alone first.** Each evaluator fills in their own copy without seeing the others; Nielsen recommends 3–5 evaluators, because each finds different problems. Then merge the lists and agree on severities.
2. **Two passes per screen:** first play through normally, then go through the heuristics one by one.
3. **Every finding gets evidence:** what you saw, where (screen, size, device), and a screenshot or file if possible.
4. **Rate severity** on Nielsen's scale (below), considering how often it happens, how bad it is when it does, and whether players can work around it.
5. **Also note what works.** That's evidence too, and it stops good things being "fixed" away.

## Severity (Nielsen)

| | Meaning |
|---|---|
| 0 | Not a usability problem |
| 1 | Cosmetic: fix if there's time |
| 2 | Minor: low priority |
| 3 | Major: important to fix |
| 4 | Catastrophe: must fix before release |

## The 10 heuristics (short)

| # | Heuristic | Ask |
|---|---|---|
| H1 | Visibility of system status | Does the player always know what's happening and what just happened? |
| H2 | Match between the system and the real world | Words, images and actions the player knows from real life (here: Leeuwarden's real bins)? |
| H3 | User control and freedom | Can the player undo, go back, leave, without losing more than they expect? |
| H4 | Consistency and standards | Same words and patterns for the same things, and as on other sites and apps? |
| H5 | Error prevention | Does the design stop slips before they happen? |
| H6 | Recognition rather than recall | Is what's needed visible, instead of remembered? |
| H7 | Flexibility and efficiency of use | Ways for new and practised players, on any device? |
| H8 | Aesthetic and minimalist design | Only what's needed on screen, with clear hierarchy? |
| H9 | Help users recognise, diagnose and recover from errors | Plain-language errors that say what happened and what to do? |
| H10 | Help and documentation | Help available when and where it's needed? |
